## Interview questions and reference answers / 面试问题与参考答案

### What does constructor injection do here? / 构造函数注入做了什么？

`EventsController(EventService eventService)` declares what the controller needs. ASP.NET Core creates the controller and supplies the registered service. The controller handles HTTP; the service performs validation and storage operations. Registering a service alone does not make the controller use it.

构造函数声明控制器需要的依赖，ASP.NET Core 创建控制器时传入已注册的服务。控制器负责 HTTP，服务负责验证和存储。只有注册而没有注入和调用，控制器不会自动使用服务。

### Why singleton, and what does it not guarantee? / 为什么使用单例？它不保证什么？

A singleton is reused within this application service provider, so later requests see the same instance-owned list. A scoped service gets a new instance for each HTTP request; with this design, each instance would start with its own seed data. Singleton registration does not make List thread-safe, persist data across restarts, or share it across processes. See [Microsoft DI guidance](https://learn.microsoft.com/dotnet/core/extensions/dependency-injection-guidelines).

单例让请求共享同一个实例字段。Scoped 在每个请求内使用一个实例；本项目的数据在实例字段里，因此不同请求会得到各自的列表。单例不等于线程安全，也不等于数据库持久化。

### Why use both a lock and copies? / 为什么既要锁又要副本？

The lock prevents list operations and multi-property updates from interleaving with other store operations. A copy prevents a returned Event from exposing the stored object's mutable reference. JSON serialization happens after the service returns and releases its lock; an independent snapshot remains coherent then. `ToArray()` creates the list snapshot while the lock is held; returning a deferred LINQ query would move enumeration outside the lock.

锁保证存储操作之间互斥；副本防止外部修改内部对象，也避免序列化时读到更新了一半的数据。`ToArray()` 在锁内立即执行查询，而不是把延迟执行的查询带到锁外。

### Why are these methods synchronous? / 为什么这些方法是同步的？

These methods perform short in-memory operations, with no asynchronous I/O to await. Adding Task.Run would schedule extra work without providing asynchronous database or network access. Async/await will be studied with the request lifecycle and future I/O needs.

这些操作只访问内存，没有需要等待的异步 I/O；不需要为了使用 async 而添加 Task.Run。

## Limits and next step / 限制与下一步

The lock serializes storage access, and copying costs allocation proportional to the returned data. These are simple trade-offs for a small Week 1 store. Separate processes have separate data, restarts lose changes, and stale client updates are still last-write-wins. This is not a booking capacity concurrency solution. Authentication and persistence remain future roadmap work.
