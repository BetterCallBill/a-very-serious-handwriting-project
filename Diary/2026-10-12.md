### Q: Why pass the current time into EventRequestValidator? / 为什么把当前时间传入验证器？

**Answer:** It makes time an explicit input, so the same request and time produce the same result. Tests can check past, equal, and future boundaries without depending on the wall clock. The validator returns validation information; the controller turns it into an HTTP response.

**参考回答：** 时间成为显式输入，同样的请求和时间得到同样的结果。测试可以固定过去、相等和未来边界，不依赖系统时钟。验证器返回验证信息，控制器负责转换成 HTTP 响应。

### Q: Does [.. _events] isolate callers from the stored Event objects? / 复制集合能隔离其中的事件对象吗？

**Answer:** No. It creates a new outer collection but copies the references to the same Event objects. Changing an event's title is visible through other references to that event. Removing an element from a separate mutable list changes that list's membership, not the original list. Collection isolation and object isolation are different.

**参考回答：** 不能。它创建新集合，但元素仍引用同一批 Event 对象。修改事件标题会被其他引用看到；从另一个可变列表删除元素，只改变那个列表的成员，不影响原列表。集合隔离不等于对象隔离。

### Q: What happens if each request gets a new EventService with instance-owned storage? / 每次请求都创建新服务实例会怎样？

**Answer:** Each instance starts with its own collection and newly initialized sample events. Data added only to the previous instance does not appear in the new instance. We must deliberately choose the storage lifetime and keep all endpoints using the same intended store; shared lifetime alone does not provide thread safety or persistence.

**参考回答：** 每个实例都有独立集合和重新初始化的示例事件。只添加到旧实例的数据不会出现在新实例中。需要明确存储生命周期并让所有端点使用预期的同一存储；共享生命周期本身不保证线程安全或持久化。

## C# interview questions / C# 面试题

### Q: How does assignment differ between value types and reference types? / 值类型与引用类型赋值有何区别？

**Answer:** Value types store their data directly. Reference-type variables hold references to objects. Assigning a value-type variable copies its value, while assigning a reference-type variable copies the reference.

**参考回答：** 值类型赋值时会复制字段值，而引用类型赋值时只会复制对象引用。两个引用变量可能指向同一个对象。

```csharp
// Value Type
int a = 10;
int b = a;

b = 20;

Console.WriteLine(a); // 10

// Reference Type
var p1 = new Person { Name = "Billy" };
var p2 = p1;

p2.Name = "John";

Console.WriteLine(p1.Name); // John
```

| Value Type | Reference Type |
|---|---|
| `int`, `bool`, `struct`, `enum` | `class`, `record class`, `array`, `string` |
| Assignment copies the value | Assignment copies the reference |
| Variables have independent field values | Variables can share an object |
| Can contain reference-type fields | Can contain value-type fields |

**面试陷阱：** Value Type 不一定存储在 Stack，Reference Type 也不意味着变量本身一定存储在 Heap。具体存储位置取决于运行时上下文。

### Q: What is a shallow copy versus a deep copy? / 浅拷贝和深拷贝有什么区别？

**Answer:** A shallow copy creates a new outer object but shares references to nested objects. A deep copy creates independent copies of the nested mutable objects as well.

**参考回答：** 浅拷贝创建新的外层对象，但内部引用类型成员仍然共享。深拷贝则会复制内部的可变引用对象，使副本可以独立修改。

假设：

```csharp
public class Address
{
    public string City { get; set; }
}

public class Person
{
    public string Name { get; set; }
    public Address Address { get; set; }

    public Person ShallowCopy()
    {
        return (Person)MemberwiseClone();
    }

    public Person DeepCopy()
    {
        return new Person
        {
            Name = Name,
            Address = new Address
            {
                City = Address.City
            }
        };
    }
}
```

使用浅拷贝：

```csharp
var p1 = new Person
{
    Name = "Billy",
    Address = new Address { City = "Sydney" }
};

var p2 = p1.ShallowCopy();

p2.Name = "John";
p2.Address.City = "Melbourne";

Console.WriteLine(p1.Name);         // Billy
Console.WriteLine(p1.Address.City); // Melbourne
```

使用深拷贝：

```csharp
var p3 = p1.DeepCopy();

p3.Address.City = "Brisbane";

Console.WriteLine(p1.Address.City); // Melbourne
Console.WriteLine(p3.Address.City); // Brisbane
```

**关键区别：** 浅拷贝共享 `Address`，深拷贝则创建新的 `Address`。

### Q: What does MemberwiseClone() copy, and how can you call it? / MemberwiseClone() 复制什么，如何调用？

**Answer:** `MemberwiseClone()` is a protected method inherited from `System.Object`. It creates a shallow copy by copying all instance fields. Value-type fields are copied by value, while reference-type fields retain references to the same objects.

**参考回答：** `MemberwiseClone()` 是 `System.Object` 提供的 `protected` 方法，用于创建对象的浅拷贝。它复制所有实例字段，包括私有字段，但不会递归复制引用对象。

方法定义：

```csharp
protected object MemberwiseClone();
```

由于它是 `protected`，不能在普通外部代码中直接调用：

```csharp
var copy = person.MemberwiseClone(); // Compile error
```

通常需要在类内部封装：

```csharp
public Person Clone()
{
    return (Person)MemberwiseClone();
}
```

**需要掌握的细节：** `MemberwiseClone()` 复制的是字段（Fields），而不是通过属性的 Getter 和 Setter 逐个复制。自动属性的 Backing Fields 也会被复制。它不会调用普通构造函数重新初始化对象，也不会自动执行深拷贝。

官方文档：[Microsoft — MemberwiseClone](https://learn.microsoft.com/en-us/dotnet/api/system.object.memberwiseclone)

### Q: What does protected mean, and why can a derived class access it? / protected 是什么，为什么派生类可以访问？

**Answer:** `protected` is an access modifier that allows a class member to be accessed within its declaring class and by derived classes. It prevents unrelated external classes from accessing that member directly.

**参考回答：** `protected` 是 C# 的访问修饰符，允许当前类及其派生类（子类）访问成员，但不允许无关的外部类直接访问。

例如：

```csharp
public class Animal
{
    protected string Name = "Dog";

    protected void Eat()
    {
        Console.WriteLine("Eating...");
    }
}

public class Dog : Animal
{
    public void ShowInfo()
    {
        Console.WriteLine(Name); // Allowed
        Eat();                   // Allowed
    }
}
```

外部调用：

```csharp
var dog = new Dog();

dog.ShowInfo(); // Allowed
dog.Eat();      // Compile error
```

**为什么 `Dog` 可以访问 `Eat()`？**

因为 `Dog` 继承了 `Animal`，因此可以访问父类中允许派生类访问的 `protected` 成员。

### Q: How do the six access levels compare? / 六种访问级别有何区别？

**Answer / 参考回答：**

| Modifier | Same Class | Derived Class | Unrelated External Class |
|---|---|---|---|
| `public` | Yes | Yes | Yes |
| `private` | Yes | No | No |
| `protected` | Yes | Yes | No |
| `internal` | Yes | Same assembly | Same assembly |
| `protected internal` | Yes | Yes | Same assembly |
| `private protected` | Yes | Same assembly only | No |

这里的表格针对常见的类成员访问场景。`protected internal` 表示**同一程序集内，或者其他程序集中的派生类**可以访问；`private protected` 则要求访问代码位于同一程序集，并且满足当前类或派生类的条件。

### Q: When should you use protected rather than expose a public member? / 何时应使用 protected？

**Answer:** Use `protected` when derived classes need access to implementation details that should remain hidden from unrelated external code. It is commonly used in inheritance-based designs and extensible frameworks.

**参考回答：** 当你希望子类可以复用或扩展父类的部分功能，但不希望外部代码直接调用这些功能时，可以使用 `protected`。

例如：

```csharp
public abstract class BaseService
{
    protected void Log(string message)
    {
        Console.WriteLine(message);
    }
}

public class UserService : BaseService
{
    public void CreateUser()
    {
        Log("Creating user...");
    }
}
```

这里 `UserService` 可以调用 `Log()`，但外部无法通过 `UserService` 实例直接调用该方法。

**面试重点：** `protected` 是面向对象编程中 Encapsulation（封装）和 Inheritance（继承）的结合。不过，不应该仅仅为了让子类方便访问，就把大量内部状态暴露为 `protected`。

### Q: How do class, record, and struct differ in assignment and copying? / 三者的赋值与复制行为有何区别？

**Answer:** A class is a reference type, a struct is a value type, and a record can be either. The `with` expression on a record creates a shallow copy by default.

**参考回答：** `class` 是引用类型，`struct` 是值类型，`record` 可以是引用类型或值类型。`record` 的 `with` 表达式默认进行浅拷贝，而不是深拷贝。

| Type | Assignment | Copy Behavior |
|---|---|---|
| `class` | Copies reference | Explicit copying required |
| `record class` | Copies reference | `with` creates a shallow copy |
| `struct` | Copies field values | Reference fields remain shared |
| `record struct` | Copies field values | `with` copies the struct value |

例如：

```csharp
public record Person(string Name, Address Address);

var p1 = new Person(
    "Billy",
    new Address { City = "Sydney" }
);

var p2 = p1 with { Name = "John" };

p2.Address.City = "Melbourne";

Console.WriteLine(p1.Name);         // Billy
Console.WriteLine(p1.Address.City); // Melbourne
```

**面试陷阱：** `record` 提供基于值的相等性语义，但并不保证不可变性，也不保证内部对象会被深拷贝。

### Q: Why can attaching a copied EF Core entity cause a tracking conflict? / 为什么跟踪复制的 EF Core 实体可能冲突？

**Answer:** EF Core uses an identity map in its Change Tracker. A single `DbContext` can track only one entity instance for a given entity type and primary key. Attaching a cloned entity with the same key can cause a tracking conflict.

**参考回答：** EF Core 的 Change Tracker 在同一个 `DbContext` 中，只允许跟踪一个特定实体类型、特定主键的对象实例。如果复制一个已经被跟踪的 Entity，再尝试跟踪副本，可能产生冲突。

例如：

```csharp
var user = await context.Users.FindAsync(1);

var copiedUser = new User
{
    Id = user.Id,
    Name = "John"
};

context.Users.Update(copiedUser); // Exception
```

原因是同一个 `DbContext` 已经在跟踪 `Id = 1` 的 `User`。

推荐直接修改被跟踪的实体：

```csharp
var user = await context.Users.FindAsync(1);

if (user != null)
{
    user.Name = "John";
    await context.SaveChangesAsync();
}
```

**什么时候使用 `AsNoTracking()`？**

当查询只用于读取数据、不需要 EF Core 自动检测和保存修改时：

```csharp
var users = await context.Users
    .AsNoTracking()
    .ToListAsync();
```

这样可以减少 Change Tracking 的开销。

但 `AsNoTracking()` 不会让实体变成不可变对象，也不会自动解决所有重复主键跟踪问题。

官方文档：[Microsoft — EF Core Identity Resolution](https://learn.microsoft.com/en-us/ef/core/change-tracking/identity-resolution)

### Q: When should you choose shallow copying, deep copying, DTO mapping, or immutable objects? / 如何选择复制或对象设计方式？

**Answer:** Shallow copying is useful when nested objects can safely be shared. Deep copying is appropriate when changes to nested mutable data must not affect the original. In many production systems, immutable objects and selective copying are preferable to cloning entire object graphs.

**参考回答：** 浅拷贝适合可以安全共享内部对象的场景，深拷贝适合需要完全隔离可变数据的场景。实际项目中，通常优先考虑不可变对象或只复制需要修改的部分。

| Scenario | Recommended Approach |
|---|---|
| Copy a simple C# object | Shallow Copy |
| Edit a nested object independently | Deep Copy or selective copying |
| Update React State | Structural Sharing |
| Create an editable form draft | Deep Copy when necessary |
| Return EF Core data to frontend | DTO Mapping |
| Update a tracked EF Core Entity | Modify tracked instance |
| Share configuration across threads | Immutable Objects |
| Create a new database record | Explicit mapping with new identity |

### Q: What's the difference between protected, private, internal, and protected internal? / 四种访问修饰符有何区别？

**Answer:** `private` limits access to the containing type; `protected` also allows derived types; `internal` allows code in the same assembly; `protected internal` allows either the same assembly or derived types. The last rule is OR, not AND. Instance-member access through a base-typed receiver has additional protected-access restrictions.

**参考回答：** `private` 限于包含类型；`protected` 还允许派生类型；`internal` 允许同一程序集；`protected internal` 允许同一程序集或派生类型，两者是“或”关系。通过基类类型的引用访问受保护实例成员，还需要满足额外的访问规则。

### Q: How do encapsulation, inheritance, abstraction, and polymorphism differ? / 封装、继承、抽象和多态有什么区别？

**Answer:** Encapsulation controls access to state and behaviour. Inheritance derives a type from a base type. Abstraction exposes a useful contract while hiding implementation details. Polymorphism lets callers use a shared interface or base type while runtime implementations supply different behaviour. For our platform, an event-storage interface could hide whether storage uses memory or a database; both implementations could satisfy the same contract. This is a design example, not an existing project feature.

**参考回答：** 封装控制状态和行为的访问；继承从基类派生类型；抽象暴露有用的契约并隐藏实现细节；多态让调用方通过共同接口或基类使用不同实现。例如事件存储接口可以隐藏内存和数据库的差异，两种实现遵守相同契约。这是设计示例，并非项目已实现的功能。

### Q: How do readonly, const, init, and required relate to immutability? / 这些关键字与不可变性有什么关系？

**Answer:** For fields, `readonly` restricts reassignment to declaration or the appropriate constructor; it does not freeze a referenced object. `const` requires a compile-time constant, and a const member is implicitly static. An `init` accessor permits property assignment during construction but does not freeze nested objects. `required` normally requires callers to initialize a member; it does not enforce a non-null or valid business value, and a constructor marked `SetsRequiredMembers` bypasses that caller check. None alone guarantees deep immutability.

**参考回答：** 对字段而言，`readonly` 限制在声明或相应构造函数中赋值，不会冻结引用对象；`const` 要求编译期常量，常量成员隐式为静态；`init` 限制属性在构造阶段赋值，不会冻结嵌套对象；`required` 通常要求调用方初始化成员，不保证非空或业务有效性，标记 `SetsRequiredMembers` 的构造函数可绕过调用方检查。单独使用这些关键字都不能保证深层不可变性。

Microsoft references: [readonly](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/readonly), [const](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/const), [init](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/init), [required](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/required).
